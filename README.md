# منصة حلقات الشيخ محمد البراك

منصة رقمية لإدارة حلقات تحفيظ القرآن الكريم — التسميع اليومي، متابعة الحفظ والإتقان، التحفيز، والمتابعة الأسرية.
مبنيّة على وثيقة المتطلبات **SRS 4.0**، وتعمل **Offline-first** (تظل تعمل عند ضعف الشبكة في المسجد).

> ﴿ وَلَقَدْ يَسَّرْنَا الْقُرْآنَ لِلذِّكْرِ فَهَلْ مِن مُّدَّكِرٍ ﴾

---

## المكوّنات

| الطبقة | التقنية |
|---|---|
| الواجهة | صفحة ويب واحدة (HTML/CSS/JS)، RTL، بلا اعتماديات بناء |
| قاعدة البيانات | **Supabase (PostgreSQL)** عبر `@supabase/supabase-js` |
| المزامنة | Offline-first: تعمل ببيانات محلية عند غياب الاتصال، وتكتب للقاعدة عند توفّره |

## البوابات (RBAC)

المشرف العام · معلم الحلقة · الإداري (شؤون الطالب) · المُسمِّع (الحصاد) · ولي الأمر · الطالب البالغ · الداعم/الكافل.
بدّل الدور من القائمة أعلى يمين الشاشة.

## الوظائف الرئيسية

- **التسميع اليومي** — رصد حضور بلمسة، تحديد آية البدء تلقائياً، إنجاز فوري، تصنيف أخطاء (لفظي/عادي/شكّ) بتكرار إلزامي، خمسة الإتقان.
- **الإدارة** — لوحة قيادة، بورصة الإنجاز، القبول وقائمة الانتظار، الأعذار، الربط والمراجعة، التقارير، سجل التدقيق.
- **ولي الأمر** — متابعة الأبناء بالألوان، الموافقات والدفع والتبرّع.
- **الطالب** — البرنامج والنقاط، سوق الحلقة، سجل QR.
- **المُسمِّع** — جلسات الحصاد واعتماد الاجتياز.
- **الداعم** — تقارير الأثر (بلا بيانات حسّاسة).
- إضافةً إلى: البوابة المالية، سوق الحلقة، شاشة المسجد (Kiosk)، ومحرك الإشعارات.

## التشغيل محلياً

لأن المشروع صفحة ثابتة، يكفي خادم ملفات بسيط:

```bash
# أي خيار:
python3 -m http.server 8080
# أو
npx serve .
```

ثم افتح: `http://localhost:8080`
بدون إعداد Supabase تعمل المنصة مباشرةً ببيانات تجريبية (Offline).

## الربط بقاعدة بيانات Supabase

1. أنشئ مشروعاً مجانياً على [supabase.com](https://supabase.com).
2. من **SQL Editor** الصق محتوى `supabase/schema.sql` ثم **Run** (يُنشئ الجداول والبذور).
3. من **Project Settings → API** انسخ `Project URL` و`anon public key`.
4. انسخ ملف الإعداد وعبِّئه:

```bash
cp js/config.example.js js/config.js
# ثم حرّر js/config.js وضع url و anonKey
```

5. أعد فتح الصفحة — ستظهر شارة **«متصل بقاعدة البيانات»** أعلى الشاشة، وتُحفظ عمليات التسميع والقبول والدفع في القاعدة.

> `js/config.js` متجاهَل في git (لا تُرفع مفاتيحك). الحماية الفعلية عبر سياسات RLS في Supabase، وتُشدَّد لاحقاً حسب مصفوفة الصلاحيات وحماية بيانات القُصّر (PDPL).

## النشر

أي استضافة مواقع ثابتة تصلح (Vercel · Netlify · GitHub Pages · Cloudflare Pages).
ارفع محتوى المجلد كما هو، وأضف `js/config.js` في بيئة النشر.

## بنية المشروع

```
albrrak/
├─ index.html              # التطبيق الكامل (كل البوابات)
├─ js/
│  ├─ db.js                # طبقة الوصول للبيانات (Supabase + offline)
│  └─ config.example.js    # قالب مفاتيح الاتصال
├─ supabase/
│  └─ schema.sql           # مخطط قاعدة البيانات + بذور
└─ README.md
```

## خارطة الطريق (حسب خطة المراحل)

- **0م (الحالية):** نواة التسميع والإدارة والتحفيز — مربوطة بقاعدة البيانات.
- **1م:** بوابة دفع سعودية فعلية (Apple Pay / STC Pay) وتكامل «نفاذ».
- **2م:** نظام المصحف المتكامل بصور مرخّصة، الحصاد والإجازات.
- **3م–4م:** سوق موسّع، شاشات المسجد الحيّة، تطبيقات الجوال، والتوسّع.
