# منصة حلقات الشيخ محمد البراك

منصة رقمية لإدارة حلقات تحفيظ القرآن الكريم — التسميع اليومي، متابعة الحفظ والإتقان، التحفيز بالنقاط، والمتابعة الأسرية.
مبنيّة على وثيقة المتطلبات **SRS 4.0**، وتعمل **Offline-first** (تظل تعمل عند ضعف الشبكة في المسجد وتُزامن لاحقاً).

> ﴿ وَلَقَدْ يَسَّرْنَا الْقُرْآنَ لِلذِّكْرِ فَهَلْ مِن مُّدَّكِرٍ ﴾

---

## التقنيات

| الطبقة | التقنية |
|---|---|
| الواجهة | صفحة ويب واحدة (HTML/CSS/JS)، RTL، بلا خطوة بناء (build-free) |
| نظام التصميم | `css/styles.css` — هوية مؤسسية، خط **IBM Plex Sans Arabic** (الواجهة) و**Amiri** (الآيات)، ألوان الشعار الذهبي/الزيتوني |
| قاعدة البيانات | **Supabase (PostgreSQL)** عبر `@supabase/supabase-js` |
| المصادقة | Supabase Auth — جوال + كلمة سر (بريد اصطناعي داخلي، بلا SMS) |
| المزامنة | Offline-first: طابور مزامنة محلي (`localStorage`) يُعاد إرساله عند عودة الاتصال |
| PWA | `manifest.webmanifest` + `sw.js` — تُثبَّت وتعمل دون اتصال |
| الاستضافة | Vercel (ثابتة) — `vercel.json` بترويسات أمان |

## البوابات (RBAC)

المشرف العام · مدير الحلقات · الإداري (شؤون الطالب) · المُسمِّع (الحصاد) · ولي الأمر · الطالب البالغ · الداعم/الكافل.
الأدوار الإدارية تُمنح من الإدارة؛ التسجيل الذاتي مقصورٌ على **ولي أمر / طالب** (مطابقةً لمصفوفة الصلاحيات SRS 5.4).

## بنية المشروع

```
albrrak/
├─ index.html                # هيكل التطبيق (يربط الأنماط والسكربتات)
├─ css/
│  └─ styles.css             # نظام التصميم الكامل
├─ js/
│  ├─ app.js                 # منطق التطبيق وكل البوابات (١٩ شاشة)
│  ├─ db.js                  # طبقة البيانات + المصادقة + طابور المزامنة
│  ├─ config.js              # مفاتيح Supabase العامة (آمنة للنشر مع RLS)
│  └─ config.example.js      # قالب المفاتيح
├─ supabase/
│  ├─ schema.sql             # الجداول والأنواع والبذور
│  ├─ auth_profiles.sql      # جدول الحسابات (profiles)
│  └─ rls_policies.sql       # سياسات الأمان الإنتاجية بالأدوار (إلزامي)
├─ assets/favicon.svg
├─ manifest.webmanifest · sw.js
└─ vercel.json               # ترويسات أمان وتخزين مؤقت
```

## التشغيل محلياً

```bash
python3 -m http.server 8080    # أو:  npx serve .
```
ثم افتح `http://localhost:8080`. بدون إعداد Supabase تعمل المنصة ببيانات تجريبية (Offline).

## الربط بقاعدة بيانات Supabase (خطوات الإنتاج)

1. أنشئ مشروعاً على [supabase.com](https://supabase.com).
2. في **SQL Editor** شغّل الملفات **بهذا الترتيب**:
   1. `supabase/schema.sql` — الجداول والبذور.
   2. `supabase/auth_profiles.sql` — جدول الحسابات.
   3. `supabase/rls_policies.sql` — **سياسات الأمان (إلزامي قبل أي بيانات حقيقية).**
3. من **Project Settings → API** انسخ `Project URL` والمفتاح العام، وضعهما في `js/config.js`.
4. من **Authentication → Providers → Email** فعّل الدخول، وللنموذج يمكن **تعطيل تأكيد البريد**.
5. سجّل حسابك من الواجهة، ثم **عيّن نفسك مشرفاً عاماً** مرّة واحدة في SQL Editor:
   ```sql
   update public.profiles set role = 'general'
   where id = (select id from auth.users where email = 'u<أرقام جوالك>@albrrak.app');
   ```

> بعد هذه الخطوات: لا يستطيع غير المُصادَق قراءة أي بيانات، ولا يستطيع أحدٌ ترقية دوره بنفسه.

## الأمان (ما طُبّق)

- **RLS بالأدوار**: لا وصول لغير المُصادَقين؛ الكادر يُشغّل، وليّ الأمر يرى أبناءه، والطالب سجلّه فقط.
- **منع تصعيد الصلاحيات**: التسجيل الذاتي بدور غير مميّز فقط، وتغيير الدور محميٌّ بـ Trigger.
- **ترويسات أمان** عبر `vercel.json`: `Content-Security-Policy`، `HSTS`، `X-Frame-Options: DENY`، وغيرها.
- **بيانات القُصّر** (الجوال/الهوية) لا تُقرأ إلا من الكادر المخوّل — امتثالاً لـ PDPL.

> المفتاح العام في `js/config.js` آمنٌ للنشر **لأن** الحماية الفعلية عبر RLS. لا تضع المفتاح السرّي (`sb_secret_...`) في المستودع أبداً.

## النشر على Vercel

المشروع ثابت — اربط المستودع بـ Vercel وانشر مباشرةً (بلا أمر بناء ولا مجلد إخراج).
`vercel.json` يضيف ترويسات الأمان والتخزين المؤقت تلقائياً. تأكّد من وجود `js/config.js` في المستودع.

## العمل دون اتصال (PWA)

Service Worker يخزّن هيكل التطبيق ويخدمه دون اتصال، ونداءات Supabase تمرّ للشبكة.
الكتابات أثناء الانقطاع تُحفظ في طابور محلي وتُرسَل تلقائياً عند عودة الاتصال.

## خارطة الطريق (خطة المراحل — SRS 13)

- **0م (الحالية):** نواة التسميع والإدارة والتحفيز — مربوطة بقاعدة البيانات ومؤمّنة.
- **1م:** بوابة دفع سعودية فعلية (Apple Pay / STC Pay) وتكامل «نفاذ».
- **2م:** نظام المصحف المتكامل بصور مرخّصة، الحصاد والإجازات.
- **3م–4م:** سوق موسّع، شاشات المسجد الحيّة، تطبيقات الجوال، والتوسّع.
