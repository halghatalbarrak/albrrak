# منصة حلقات البراك

منصة إدارة حلقات التحفيظ (القاعدة المدنية • مراقي). أُعيد بناؤها بمخطط نظيف وفق
`DESIGN.md` (٥٠ قرارًا) و`BUILD_PLAN.md`.

> **الحالة:** المرحلة صفر (م٠) — الأساس والأمان. القلب (المراحل، المسارات،
> الجلسة، الحصاد، الشهادات) يُبنى في المراحل التالية.

---

## المكدَّس التقني

| الطبقة | التقنية |
|---|---|
| الإطار | **Next.js** (App Router) |
| اللغة | **TypeScript** (strict) |
| الأنماط | **Tailwind CSS** + `src/app/legacy.css` (نظام RTL منقول) |
| قاعدة البيانات | **Supabase (PostgreSQL)** |
| ORM والترحيلات | **Prisma** — مصدر الحقيقة الوحيد للمخطط |
| الأمان | RLS مغلقة على كل جدول (بلا سياسة مفتوحة) + ترويسات `vercel.json` |
| النشر | **Vercel** |

```
albrrak/
├─ DESIGN.md · BUILD_PLAN.md      # مرجعا الحقيقة

```

## قاعدة العمل الحاكمة

**لا commit إلا بعد أن تخضرّ الثلاثة:**

```bash
npx tsc --noEmit && npm run lint && npm run build
```

Prisma هو المصدر الوحيد للمخطط — **لا SQL يدوي في لوحة Supabase**. كل تغيير = ترحيل مرقّم.

## أول تشغيل حيّ (Live bootstrap)

> **من يُثبت هذا أنت، لا الوكيل.** الشاشات (`/login`, `/me`, `/admin/applications`)
> متحقَّقة بالبناء والأنواع، لكن **لم تُشغَّل على Supabase حيّ من هنا** (الشبكة محجوبة).
> الخادم (المصادقة والصلاحية والمسارات) مُختبَرٌ على Postgres حقيقي (44 اختبارًا).

**الأسرار** (Vercel → Settings → Environment Variables، **و**GitHub → Secrets):

| السرّ | المصدر |
|---|---|
| `DATABASE_URL` · `DIRECT_URL` | Supabase → Database |
| `NATIONAL_ID_ENC_KEY` | `openssl rand -base64 32` — **احفظه خارج القاعدة** |
| `SUPABASE_JWT_SECRET` | Supabase → API → JWT Secret |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → API Keys → `service_role` 🔴 **يتجاوز RLS** |
| `NEXT_PUBLIC_SUPABASE_URL` · `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase → API (عامّان) |

**الخطوات — ونتيجة كلٍّ المتوقعة:**

1. **طبّق الترحيلات:** شغّل workflow «Migrate (deploy)» ← اكتب `APPLY`.
   المتوقع: **٦ ترحيلات، ٢٦ جدولًا**، بذرة ٥ مراحل + ٢ جنسية، RLS على الكل.
   تحقّق: `curl -H "apikey: <anon>" ".../rest/v1/Student?select=id&limit=1"` ← `[]` أو 401/403.
2. **أنشئ أوّل مدير (بزرّ، بلا طرفية):**
   أ) Supabase → Authentication → Users → Add user: البريد `u<جوالك>@albrrak.app` + كلمة سر. انسخ الـ**User UID**.
   ب) GitHub → **Actions** → **Bootstrap admin** → Run workflow: الصق `authUid` (الـUID) و`phone` (جوالك) و`name` (اسمك) و`confirm` = `BOOTSTRAP`.
   المتوقع في السجل: «المدير جاهز» (أدواره: SUPER_ADMIN, CIRCLE_MANAGER, REGISTRAR). وإن وُجد مديرٌ سلفًا: «مدير موجود بالفعل — لن يُنشأ ثانٍ».
   > يظهر الزر بعد أن يصل الـworkflow إلى الفرع الافتراضي (main). يقرأ `DATABASE_URL`/`DIRECT_URL` من GitHub Secrets.
3. **القيد:** افتح `https://<vercel>/apply` ← املأ النموذج (تظهر الجنسيات/المراحل المبذورة) ← أرسل.
   المتوقع: «تمّ استلام طلب القيد». ⟵ **يُثبت Vercel + Prisma/pooler + التشفير + RLS دفعةً.**
4. **الدخول والقبول:** `/login` بجوالك وكلمة سرك ← تُوجَّه إلى `/me`. ثم `/admin/applications`
   ← ترى الطلب بكل خبره ← «قبول». المتوقع: ينجح (يُنشئ الطالب؛ و≥١٣ يُنشئ مستخدم مصادقته).
5. **الطالب يرى صفحته:** أنشئ للطالب (≥١٣) كلمة سر في Supabase Users ← `/login` بجواله ←
   `/me` يعرض: «حالتك: بانتظار اختبار القراءة». ⟵ **قيدٌ ← قبول ← دخول ← رؤية: مشى المكدَّس.**

## المعمارية — الحدّ يُغني عن الانضباط

**كل كتابة تمرّ بدالّة خدمة في `src/server/**`.** المسارات والمكوّنات **لا تستورد عميل
Prisma مباشرةً** — قاعدة ESLint (`no-restricted-imports`) تُسقط البناء عند الخرق:

```
src/lib/prisma.ts     ← عميل القاعدة (يُستورَد من src/server/** فقط)
src/server/**         ← دوالّ الخدمة (القواعد المطلقة تُنفَّذ هنا) + auth
src/app/api/**        ← Route Handlers: تستدعي الخدمة، تتحقّق من الصلاحية، لا Prisma
```

> جرّب استيراد `@/lib/prisma` في مسارٍ ⟵ `npm run lint` يفشل. فالتجاوز خطأ بناء لا اجتهاد منسيّ.

**حرّاس الأسرار (ESLint، بنيةً لا تعليقًا):**
- `SUPABASE_SERVICE_ROLE_KEY` (يتجاوز RLS) ⟵ يُقرأ في `src/server/**` فقط، وإلا فشل lint.
- أي `process.env.NEXT_PUBLIC_*` يحوي `SERVICE`/`SECRET` ⟵ فشل lint **في كل مكان** (سرٌّ لا يكون عامًّا).

**المصادقة (حقيقية — لا شِمّة):** `src/server/auth.ts` يتحقّق من **JWT من Supabase**
(`Authorization: Bearer`) بسرّ التوقيع، ثم يحلّ `sub ← User.authId ← الأدوار`. **لا رأس هوية
يُصدَّق أبدًا.** بلا JWT ⟵ 401 • مستخدم معطَّل/غير موجود ⟵ 403 • دور غير كافٍ ⟵ 403.

> **بنيةٌ لا تعليق:** `User.authId` فارغٌ لمن دون ١٣ ⟵ لا `sub` يحلّ إليه ⟵ يستحيل انتحاله.
> وبلا `SUPABASE_JWT_SECRET` تفشل المسارات المحميّة **مغلقةً** (لا وصول) — الفشل الآمن.

## الاختبارات (قاعدة العمل ٤)

القواعد المطلقة (م١/م٣/م٥، التفويض، الاعتمادات) مُنفَّذة في الخادم، ولكلٍّ اختبارٌ
يثبت أن تجاوزها **يُرفض** — على Postgres حقيقي لا وهمي:

```bash
# تحتاج قاعدة Postgres اختبارية + مفتاح تشفير عابر
export DATABASE_URL="postgresql://postgres@127.0.0.1:5432/albrrak_test"
export DIRECT_URL="$DATABASE_URL"
export NATIONAL_ID_ENC_KEY="$(openssl rand -base64 32)"
npx prisma migrate deploy   # يطبّق الترحيلات على قاعدة الاختبار
npm test                    # vitest
```

في CI تعمل تلقائيًّا بخدمة Postgres (`.github/workflows/ci.yml` ← وظيفة `test`).

## ⚠️ الترتيب الحاكم عند إضافة ترحيل: Migrate **أولًا** ← ثم الدمج

الكود يُنشَر تلقائيًّا (Vercel تنشر `main` في ثوانٍ)، أمّا المخطط فينتظر زرًّا بشريًّا
(workflow **Migrate**). بينهما فجوةٌ خطيرة: **كودٌ جديد يعمل على قاعدةٍ قديمة.** إن دمجتَ
تغييرًا فيه ترحيلٌ جديد قبل تطبيقه على الإنتاج، انكسر الإنتاج فورًا (`P2022: column …
does not exist`). وهذا يتكرّر في كل مرحلةٍ تضيف ترحيلًا (م٢…م٧).

**القاعدة:** لكل تغييرٍ يحوي ترحيلًا جديدًا —

1. شغّل **Migrate (deploy)** على فرعك (Actions ← Migrate ← Run workflow على الفرع ← `APPLY`).
   يطبّق الترحيل على الإنتاج. الترحيلات **إضافية**، فالكود القديم (main الحاليّ) يتجاهل
   الأعمدة الجديدة بأمانٍ حتى تُنشَر الشيفرة الجديدة.
2. تأكّد أن وظيفة CI **`prod schema in sync`** خضراء (تقرأ `prisma migrate status` على
   الإنتاج، وتفشل صراحةً إن كان متأخّرًا — فيستحيل الدمج ونحن ناسون).
3. ثم ادمج إلى `main`.

> **لماذا حارسٌ بنيويّ لا انضباط؟** لأنّ CI العاديّة تُرحّل قاعدتها العابرة فتخضرّ وهي
> عمياء عن الإنتاج — نفس علّة `SUPABASE_JWT_SECRET`: خضرةٌ في الموضع الخطأ. الحدّ يُغني
> عن التذكّر: `prod schema in sync` يجعل «Migrate قبل الدمج» شرطًا لا عادة.

### أدوات التشخيص (`Diag *`)

`Diag DB` و`Diag Accept` (workflow_dispatch يدويّ) **تتّصل بقاعدة الإنتاج** لإخراج الخطأ
الحقيقي بدل التخمين. `Diag Accept` يعيد إنتاج كتابات القبول داخل **معاملةٍ تتراجع** — يمسّ
الإنتاج قراءةً ولا يغيّر فيه حرفًا. تُبقى لأنها أثبتت نفعها؛ لا تُشغَّل إلا عند الحاجة.

## تدوير مفتاح رقم الهوية (`NATIONAL_ID_ENC_KEY`) — قبل أول قيدٍ حقيقي

رقم الهوية (م٥) يُشفَّر بـ AES-256-GCM. **المفتاح سرّ إنتاجيّ حرج: يضيع = هوياتٌ لا تُقرأ.**

**أين يعيش:**
- **Vercel** → Project → Settings → Environment Variables (للتشغيل).
- **GitHub** → Secrets (لوظيفتَي الترحيل والاختبار).
- **نسخة احتياطية آمنة منفصلة عن القاعدة** (خزنة أسرار / KMS). ⟵ هذا هو صمّام فقدان المفتاح.

**فقدان المفتاح:** الهويات المشفَّرة به تصير **غير قابلة للقراءة — بحكم التصميم** (هذا ما يضمنه التشفير). لا استرداد إلا من النسخة الاحتياطية. والتطبيق يبقى يعمل: الجديد يُشفَّر بمفتاحٍ جديد، والقديم وحده يتعذّر فكّه. **أهون من تسريبها.**

**التدوير (مدعومٌ بلا كسر صيغة):** كل نصٍّ مخزَّن مُرقَّم بنسخته (`v1:…`). للتدوير:
1. ولّد مفتاح `v2` (`openssl rand -base64 32`)، اضبط `NATIONAL_ID_ENC_KEY_V2` في الأسرار.
2. في `src/lib/national-id.ts`: أضِف `v2` إلى `KEY_ENV`، واجعل `CURRENT_KEY_VERSION = "v2"`.
   ⟵ الكتابة الجديدة تصير `v2:`، والقديمة `v1:` **ما زالت تُفكّ** بمفتاح `v1` المحتفَظ به.
3. مهمة إعادة صياغة: لكل `User` هويّته `v1:` ← تُفكّ بـ`v1` وتُعاد بـ`v2` (بمسارٍ مخوّل مُسجَّل).
4. حين تصير كل الصفوف `v2:` ← يُسحب مفتاح `v1`.

## مولّد الشهادات (`src/server/certificate.ts`) — وحدةٌ جاهزةٌ لـم٥

وحدةٌ **قابلة لإعادة الاستخدام** تولّد صورة شهادة PNG عربية من بيانات مجرّدة:

```ts
import { renderCertificatePng } from "@/server/certificate";
const png = await renderCertificatePng({
  recipientName: "محمد عبدالله القحطاني",
  title: "شهادة اجتياز — القاعدة المدنية",
  token: "BRK-CIVIL-8F3A2C",
  verifyUrl: "https://…/verify/BRK-CIVIL-8F3A2C",
  bodyLine: "باجتيازه متطلّبات القاعدة المدنية بنجاحٍ واقتدار", // اختياري
  brand: "منصة حلقات البراك",                                  // اختياري
}); // ⟵ Buffer (PNG 1200×849)
```

**المحرّك: Chromium بلا رأس** (`puppeteer-core` + `@sparticuz/chromium`) يرسم قالب HTML/CSS
بـ`dir="rtl"`. **ولماذا لا Satori (`@vercel/og`):** Satori يضع الكلمات بترتيبها المنطقيّ دون
تطبيق خوارزمية bidi، فينعكس ترتيب الكلمات العربية («القحطاني عبدالله محمد»). المتصفّح وحده
يرتّب bidi صحيحاً. **ولا حيلة نصية تصلح ذلك** (عكسٌ يدويّ يكسر الأرقام واللاتينية والمختلط).

### ⚠️ اعتمادٌ ثقيل — والقرار المعماريّ: التوليد وقت الإصدار لا الطلب

- `@sparticuz/chromium` ≈ **٥٠MB** مضغوطًا brotli (≈ **١٧٠MB** وقت التشغيل)، **قرب حدود دالّة Vercel**.
- التوليد **بطيء عمدًا**: إقلاع بارد **~٥ ثوانٍ**، دافئ **~١٫٦s**.

> **القرار (قرار معماريّ لـم٥):** تُولَّد الشهادة **مرّة واحدة وقت الإصدار (issuance)**، تُخزَّن
> صورتها (Supabase Storage)، وتُقدَّم من التخزين. **لا يُستدعى `renderCertificatePng` في مسارٍ
> يُطلب لكل زائر** — فذلك يعني إقلاع متصفّح لكل طلب: بطءٌ وكلفةٌ وتجاوز حدود الدالّة.

### ما يجب أن يفعله مسار م٥ الذي يستدعيها

1. **`next.config.mjs`** يُبقي `serverExternalPackages: ["@sparticuz/chromium", "puppeteer-core"]`.
2. مسار الإصدار **يجب** أن يضيف `outputFileTracingIncludes` لمفتاح مساره، وإلا فشل على Vercel
   بـ `chromium/bin does not exist`:
   ```js
   outputFileTracingIncludes: {
     "/api/<مسار-إصدار-الشهادة>": [
       "./public/fonts/IBMPlexSansArabic-*.ttf",
       "./node_modules/@sparticuz/chromium/bin/**",
     ],
   }
   ```
3. **الخطوط** (IBM Plex Sans Arabic، ثلاثة أوزان) في `public/fonts/` — الوحدة **تضمّنها base64**
   من القرص، فهي **مستقلّة عن أيّ HTTP origin** (تصلح لمهمّة توليدٍ خلفية وقت الإصدار).

### مأخذٌ تقنيّ مُوثَّق في الكود

لا تستخدم `screenshot({clip})` مع `<html dir="rtl">` — أصل الإحداثيات ينزاح في RTL فتُلتقط
منطقة بيضاء فارغة. الوحدة تضبط نافذة العرض وتلتقطها **كاملةً بلا clip**.

> **الحالة:** الوحدة مُستخرَجة ومُتحقَّقٌ من إخراجها (شهادة صحيحة الترتيب على Vercel ومحليًّا)،
> لكنها **غير موصولة بأيّ مسار بعد** — تجربة `/cert-spike` أُزيلت. م٥ يصلها.
